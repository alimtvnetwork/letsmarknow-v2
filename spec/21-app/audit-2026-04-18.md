## 3. Findings — ranked by risk (highest → lowest)

> **Status legend:** 🔴 FAILING (blocks compliance) · 🟠 Partial · 🟢 OK
> All findings below are 🔴 unless noted.

### F1 🔴 No backend / Lovable Cloud not enabled
- **Spec:** `09-auth-accounts/`, `02-data-model/`, `03-api-endpoints/`, `22-infrastructure/`
- **Gap:** Spec mandates Postgres + RLS + auth + edge functions. Project has no Cloud integration, no `src/integrations/`, no env vars.
- **Status:** Not started.
- **Severity:** 10/10 · **Confidence:** 10/10 · **Risk:** critical
- **Why fails:** Without Cloud, none of the 11 entities can persist; auth, sharing, billing, sync, RLS all impossible.
- **Impact:** 100% of feature scope blocked.
- **Fix:** Enable Lovable Cloud → migrate the 11 entities → wire `user_roles` + `has_role()` per locked rules.
- **Remaining:** Auth flows, RLS policies per `permissions-matrix.json`, edge functions for share viewer / save-session / billing webhooks.
- **Blocks compliance:** YES.

### F2 🔴 No authentication or identity model
- **Spec:** `09-auth-accounts/01-identity-model.md`…`11-rate-limits-and-abuse.md`
- **Gap:** No sign-up, sign-in, password reset, email verification, OAuth, MFA, sessions.
- **Severity:** 10/10 · **Confidence:** 10/10 · **Risk:** critical
- **Why fails:** Every other gate (org membership, sharing, billing) depends on identity.
- **Fix:** Lovable Cloud auth + email/password + Google OAuth (per `04-oauth-providers.md`); create `accounts` + `user_roles`; sessions per `06-sessions.md`.
- **Remaining:** SSO/SAML (Phase 1+), MFA, device panel, rate-limit middleware (M4 still open).
- **Blocks compliance:** YES.

### F3 🔴 Zero data-model migrations
- **Spec:** `02-data-model/01-organization.md` … `11-account.md`
- **Gap:** 11 entities specified with full field tables, invariants, indexes, lifecycle, events. None exist.
- **Severity:** 10/10 · **Confidence:** 10/10 · **Risk:** critical
- **Fix:** Generate one migration per entity, UUIDv7 PKs, soft-delete columns where spec demands, RLS enabled by default, FKs `on delete cascade` per spec.
- **Remaining:** Triggers for `usage_count_cache` (Tag), history-event emission, `updated_at` triggers.
- **Blocks compliance:** YES.

### F4 🔴 Zero REST API endpoints implemented

- **Severity:** 10/10 · **Confidence:** 10/10 · **Risk:** critical

## 5. Top-priority fix sequence (the only sane order)

1. **Enable Lovable Cloud** (closes path for F1, F2, F3).
2. **Generate migrations for the 11 entities** with UUIDv7, soft-delete, RLS on (F3).
3. **Wire `user_roles` + `has_role()`** per locked Core rule, then codegen RLS from `permissions-matrix.json` (F2, F10).
4. **Wire design tokens + copy strings + error codes** modules — pure codegen from existing spec files (F11, F12, F13).
5. **Stand up `/auth`, `/dashboard`, `/share/:token`, `/onboarding`, `/billing`** routes with shells (F6).
6. **Implement Phase-0 MVP feature set** per `20-roadmap/01-phase-0-mvp.md`: save-tab, list view, collections, sharing v1, soft-delete + undo (F7, F8, F15, F17).
7. **Close spec gaps M1–M14** in parallel; without them step 6 will stall.
8. **Build extension externally** (F5) — Lovable cannot host MV3.
9. **Telemetry, search, import/export, marketing, PWA, a11y CI** (F14, F16, F18, F19, F20, F21).
10. **Tests** (F22, B4) — deferred per user, but treat as compounding debt.
